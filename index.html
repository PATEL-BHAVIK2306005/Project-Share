1. Python WSGI & Flask Core Architecture 8 Questions
Q1What is Flask and why is it classified as a microframework?
+
Task 1: Core Framework
Flask is a lightweight Python WSGI web framework built on Werkzeug and Jinja2. It is classified as a "microframework" because it does not enforce a rigid project structure, specific ORM, or built-in form validation out-of-the-box, allowing developers complete architectural freedom to integrate custom libraries.
Q2Explain the WSGI (Web Server Gateway Interface) standard (PEP 3333).
+
Task 1: WSGI Protocol
WSGI is a standard specified in PEP 3333 mediating communication between web servers (like Nginx, Apache, or Gunicorn) and Python web applications. The server receives the HTTP request, populates an environment dictionary (environ), and calls the Flask application callable with start_response to stream back HTTP status, headers, and body.
Q3How does Flask route incoming HTTP requests to view functions?
+
Task 1: Routing Engine
Flask uses route decorators like @app.route('/path', methods=['GET', 'POST']). Internally, Werkzeug matches URL paths using regular expressions against its Map and Rule routing tree. Matching path variables (e.g., <int:id>) are automatically parsed and passed as arguments to the endpoint handler function.
Q4What is the difference between Application Context and Request Context in Flask?
+
Task 1: Thread-Local Contexts
Flask manages two thread-local contexts: The Application Context (accessible via current_app and g) holds app-level configurations and database connection handles. The Request Context (accessible via request and session) encapsulates request-specific attributes such as HTTP headers, query strings, and form parameters.
Q5What are Flask Blueprints and why are they used in modular systems?
+
Task 1: Modular Architecture
A Blueprint is an organizational pattern in Flask that allows routing, views, templates, and static assets to be isolated into modular sub-applications (e.g., auth, admin, store). Blueprints improve maintainability, separation of concerns, and enable large enterprise applications to be built collaboratively across teams.
Q6How does Jinja2 prevent Cross-Site Scripting (XSS)?
+
Task 1: Templating Engine
Jinja2 has auto-escaping enabled by default for HTML templates. It automatically converts dangerous characters like <, >, &, ", and ' into safe HTML entity equivalents (e.g., &lt;), preventing malicious script injection unless an author explicitly marks content with the | safe filter.
Q7What is the advantage of Flask's `url_for()` over hardcoded URL paths?
+
Task 1: Reverse Routing
url_for() performs dynamic reverse URL resolution based on endpoint function names rather than static strings. This decouples HTML links from route paths, automatically handles URL encoding, appends query parameters, and generates cache-busting timestamp tokens for static assets.
Q8How does custom error handling work in Flask using `@app.errorhandler`?
+
Task 1: Exception Handling
The @app.errorhandler(404) and @app.errorhandler(500) decorators intercept specific HTTP status codes or unhandled Python runtime exceptions. They suppress raw server stack traces from leaking to clients and render custom error templates maintaining application branding.
2. Front-End Design & Responsive Web Integration 7 Questions
Q9How does Bootstrap 3's 12-column responsive grid system function?
+
Task 2: Responsive Grid
Bootstrap 3 utilizes a fluid 12-column layout defined via CSS media queries. It uses four core device breakpoints: Extra Small (col-xs-* <768px), Small tablets (col-sm-* ≥768px), Medium laptops (col-md-* ≥992px), and Large desktops (col-lg-* ≥1200px), summing up to 12 columns per row with 15px gutters.
Q10What is the architectural benefit of Template Inheritance (`base.html`)?
+
Task 2: UI Modularity
Template inheritance adheres to the DRY (Don't Repeat Yourself) principle. The root skeleton (base.html) defines the document structure, head metadata, Bootstrap CSS/JS CDN links, navbar, and notifications. Child templates extend it via {% extends "base.html" %} and populate isolated {% block content %} areas.
Q11What is the difference between client-side and server-side validation?
+
Task 2: Form Validation
Client-side validation (HTML5 attributes and JavaScript) provides instantaneous user feedback and reduces network roundtrips. However, client validation can easily be bypassed using curl or Postman. Therefore, strict server-side validation in Python is mandatory for data security and integrity.
Q12How are Flash Messages implemented in Flask and styled in Bootstrap?
+
Task 2: User Notifications
Flask's flash(message, category) stores notification messages temporarily inside the cryptographically signed session cookie. On the next HTTP render, Jinja2 evaluates get_flashed_messages(with_categories=true) and renders them into Bootstrap dismissible alerts (e.g., class="alert alert-success").
Q13How does the UI maintain mobile responsiveness across diverse viewports?
+
Task 2: Cross-Device UI
Responsiveness is achieved through: 1. Viewport meta tag (<meta name="viewport" content="width=device-width, initial-scale=1.0">); 2. Fluid percentage widths and CSS Flexbox; 3. CSS media queries dynamically restructuring cards and tables for handheld screens.
Q14Explain the distinction between DOM Manipulation in Vanilla JS vs jQuery.
+
Task 2: Front-End Scripting
Vanilla JavaScript utilizes native W3C Document Object Model APIs (such as document.getElementById() and element.classList.toggle()), offering maximum execution speed. jQuery provides a concise cross-browser syntactic wrapper (such as $('#id').fadeToggle()) that abstracts away browser inconsistencies.
Q15How do Bootstrap modal dialogues operate during checkout and alerts?
+
Task 2: Interactive Modals
Bootstrap modals use fixed CSS positioning (position: fixed) stacked above an active dark backdrop element (.modal-backdrop). Modals can be triggered either declaratively via HTML data attributes (data-toggle="modal") or programmatically via JavaScript ($('#modal').modal('show')).
3. Database Architecture, ORM & SQL Resilience 8 Questions
Q16What is an ORM and why use Flask-SQLAlchemy instead of raw SQL?
+
Task 3: ORM Persistence
An Object-Relational Mapper (ORM) maps database tables to Python classes and rows to Python objects. Flask-SQLAlchemy abstracts low-level SQL syntax, enforces type safety, automatically handles parameterization, and simplifies complex queries through clean Python method calls like User.query.filter_by().first().
Q17How does the application connect to MySQL inside XAMPP?
+
Task 3: DB Driver & Connection
The application utilizes the pure-Python PyMySQL DBAPI driver. The connection URI in config.py is configured as mysql+pymysql://root:@localhost:3306/majestic_db. SQLAlchemy communicates over TCP port 3306 with the XAMPP MariaDB/MySQL engine.
Q18Explain the Zero-Downtime SQLite fallback engine in `config.py`.
+
Task 3: Failover Architecture
During application boot, config.py executes an automated TCP probe testing port 3306. If the XAMPP MySQL daemon is stopped or unreachable, the system automatically redirects the database URI to local SQLite (sqlite:///pbl_framework.db), ensuring zero application crashes during viva presentations.
Q19What is SQL Injection (SQLi) and how does SQLAlchemy prevent it?
+
Task 3: SQL Injection Defense
SQL Injection occurs when untrusted user inputs are concatenated directly into SQL query strings. SQLAlchemy neutralizes SQLi by strictly utilizing parameterized prepared statements. Incoming user parameters are transmitted separately to the DB engine as literal bound data values, never as executable SQL commands.
Q20What are Primary Keys, Foreign Keys, and Referential Integrity?
+
Task 3: Relational Modeling
A Primary Key (e.g., id) uniquely identifies every individual record in a table. A Foreign Key (e.g., user_id in the orders table) references the primary key of another table, enforcing referential integrity and establishing relational associations (One-to-Many, Many-to-Many).
Q21What is Database Connection Pooling and why is it essential?
+
Task 3: Connection Pool
Connection pooling maintains an active pool of pre-established database TCP connections. Instead of repeatedly executing expensive socket handshakes for every HTTP request, Flask-SQLAlchemy borrows an existing connection from the pool and returns it upon request completion.
Q22How do `db.session.commit()` and `db.session.rollback()` uphold ACID compliance?
+
Task 3: ACID Transactions
SQLAlchemy operates within transactional sessions. Multiple database mutations are staged simultaneously. If all succeed, db.session.commit() writes them atomically. If an unhandled exception occurs, db.session.rollback() reverts all modifications, preventing database inconsistency.
Q23What are Database Indexes and when should they be added?
+
Task 3: Performance Indexing
Database indexes are auxiliary balanced search tree (B-Tree) data structures created on columns frequently used in WHERE, JOIN, or ORDER BY clauses (e.g., username, email). They reduce lookup complexity from $O(N)$ sequential table scans to $O(\log N)$ binary searches.
4. Authentication Security & Password Cryptography 8 Questions
Q24Why is storing plaintext passwords in a database a catastrophic vulnerability?
+
Task 4: Cryptographic Fundamentals
If a database is breached through SQL injection, leaked backups, or internal privilege misuse, plaintext passwords are immediately exposed. Because individuals commonly reuse identical passwords across corporate, email, and banking services, this exposes their entire digital identity.
Q25Explain the fundamental distinction between Encryption and Hashing.
+
Task 4: Cryptography
**Encryption** is a two-way mathematical process reversible with a corresponding secret decryption key (e.g., AES-GCM, RSA). **Hashing** is a one-way mathematical transformation that maps arbitrary data into a fixed-length digest that is mathematically irreversible.
Q26What is a Salt in password hashing and what attack does it neutralize?
+
Task 4: Salted Hashing
A salt is a cryptographically strong pseudo-random string appended to each user's password prior to hashing. It guarantees that two users with identical passwords produce completely different hash digests, completely neutralizing precomputed Rainbow Table and dictionary attacks.
Q27Which password hashing algorithms are utilized by Werkzeug in this project?
+
Task 4: Werkzeug Security
Werkzeug's generate_password_hash() implements modern adaptive algorithms: scrypt:32768:8:1 (memory-hard, neutralizing GPU/ASIC brute forcing) or pbkdf2:sha256 with 260,000+ iterations, producing format strings: method$salt$hash.
Q28How does Flask protect session cookies from client-side tampering?
+
Task 4: Session Integrity
Flask cryptographically signs session cookie payloads using an HMAC (Hash-based Message Authentication Code) derived from the secret app.config['SECRET_KEY']. If a client tampers with the cookie payload, the HMAC signature mismatch causes Flask to invalidate the session.
Q29What are the `HttpOnly` and `SameSite` cookie security attributes?
+
Task 4: Cookie Protection
HttpOnly prevents client-side JavaScript (via document.cookie) from reading session cookies, neutralizing session hijacking via Cross-Site Scripting (XSS). SameSite=Lax/Strict instructs browsers not to dispatch cookies on cross-origin requests, mitigating CSRF attacks.
Q30What is Cross-Site Request Forgery (CSRF) and how is it mitigated?
+
Task 4: CSRF Defense
CSRF occurs when a malicious website tricks an authenticated browser into submitting unwanted actions to a target server. It is mitigated using Synchronizer CSRF Tokens (e.g., via Flask-WTF), where every form includes a unique, unpredictable token validated server-side.
Q31What is an Audit Trail and why does `login_audit_logs` record failed attempts?
+
Task 4: Security Auditing
An Audit Trail provides an immutable chronological log of system activity. Recording both successful logins and failed attempts (with IP addresses, usernames, and timestamps) enables intrusion detection systems to recognize brute-force patterns and provides forensic evidence.
5. Razorpay Payment Gateway, SMTP & API Security 9 Questions
Q32What is the end-to-end transaction lifecycle of Razorpay Payment Gateway?
+
Task 5: Payment Architecture
1. User selects a product; 2. Flask calls Razorpay REST API (client.order.create()); 3. Razorpay returns an order_id; 4. Frontend opens Razorpay modal (checkout.js); 5. Customer authorizes transaction via UPI/Card; 6. Razorpay redirects with payment ID and signature; 7. Flask verifies cryptographic HMAC signature before database persistence.
Q33Why must payment amounts be converted to paise in Razorpay API?
+
Task 5: Currency Handling
Financial systems avoid floating-point math due to binary representation rounding inaccuracies (e.g. 0.1 + 0.2 != 0.3). Razorpay processes currency amounts in the smallest subunit (1 INR = 100 paise), guaranteeing absolute mathematical precision.
Q34How is Razorpay cryptographic signature verification performed?
+
Task 5: Cryptographic Integrity
The server constructs a payload string: order_id + "|" + payment_id. It computes an HMAC-SHA256 hash using the private key_secret via razorpay.utility.verify_payment_signature(). If the computed hash matches the returned razorpay_signature, authenticity is proven.
Q35What happens if a user alters the payment amount in browser DevTools?
+
Task 5: Tamper Proofing
The transaction will be rejected immediately. Because the order was pre-created server-side with a fixed authorized amount, Razorpay's server computes the signature using the authentic server order. Any altered client parameters result in a signature mismatch during verification.
Q36What is the difference between Test Mode and Live Mode in Razorpay?
+
Task 5: Sandbox vs Production
Test Mode (rzp_test_*) connects to Razorpay's sandbox simulator, allowing developers to simulate successful, failed, and OTP flows without transferring real money. Live Mode (rzp_live_*) communicates with authentic banking acquiring gateways and card networks.
Q37How does SMTP work and what is STARTTLS transport encryption on port 587?
+
Task 5: SMTP Relay Protocol
Simple Mail Transfer Protocol (SMTP) transmits emails between servers. On submission port 587, the client connects in plain text and immediately issues the STARTTLS command, upgrading the TCP socket to secure TLS encryption before transmitting login credentials and message contents.
Q38Why should 16-character Google App Passwords be used instead of main passwords?
+
Task 5: SMTP Authentication
Modern Google accounts enforce Two-Factor Authentication (2FA), which breaks headless SMTP daemons. A 16-character Google App Password grants isolated access strictly to the SMTP scope and can be revoked individually without changing or compromising the master account credentials.
Q39What is Payment Idempotency and why is it vital in financial systems?
+
Task 5: Financial Idempotency
Idempotency ensures that performing an operation multiple times produces the identical outcome without duplicate side effects. In payment gateways, idempotency keys ensure that if a user double-clicks the "Pay" button or experiences a network retry, they are charged only once.
Q40How are automated tax invoices generated upon successful checkout?
+
Task 5: Invoice Generation
When signature verification passes, the backend populates an HTML/CSS corporate invoice template (templates/payment_success.html) with unique invoice numbers, transaction IDs, timestamp, and itemized totals, rendering it on-screen and dispatching an electronic copy via SMTP.
